# Known patterns on these Elementor / LiteSpeed / Mirai hotel sites

Step 3 of the pass: find the root cause before changing anything. Each row is a symptom seen on a MetaHotels site,
the cause that was proven there, and the fix that held (or why there is none). Match the symptom, confirm the
cause on the live page with the tools in references/testing.md (simulate the fix with `scripts/wp/make-rules.py`
rules first), then fix in the cheapest place: Elementor settings or custom CSS on our own widget, then the site
plugin, then a metahotels-core toggle. `$S` is the skill's `scripts/` folder; tool names without a path are in
`scripts/`, `scripts/wp/` or `scripts/checks/`. Site-plugin functions named in a fix (`gevora_perf_dialog_css()`,
`kph_perf_hero_slide()`, `nassimatower-performance.php` 1.1.0 ...) are in `assets/plugin-examples/`. Where a fix needs
the owner's approval, the row says so; SKILL.md has the full list.

## Hero and largest paint

The LCP element arrives late, the hero is blank or a video costs most of the weight.

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| LCP element is a `DIV` with a background image; PSI "resource load delay" > 1 s | CSS background (classic, slideshow, or the fallback image of a background video): invisible to the preload scanner | metahotels-core toggle "Preload Hero Background Image" (`metahotels_enable_hero_preload`, 2.9.8.6+). Video-fallback images are handled from 2.9.8.8. The filters `metahotels_hero_preload_enabled` / `metahotels_hero_preload_images` let a site plugin switch it on for one page or supply an image core does not find; check the page prints exactly one `<link rel="preload" as="image">` |
| Hero is an Elementor background slideshow and on a throttled phone the LCP is slide 2 at 15 s+, or the popup's background image (`scripts/checks/lcp-timeline.js` lists every LCP candidate) | The slideshow is painted by Swiper; slide 1's image arrives after the slide has rotated away, so slide 1 never paints. Preload alone still waits for Swiper (Abar: 11.8 s) | Elementor custom CSS on the hero container: `selector{background:url(<slide 1>) center/cover no-repeat}` plus `selector:has(> .elementor-background-slideshow .swiper-slide-active){animation:<name> 0s 1.5s forwards}` with `@keyframes <name>{to{background-image:none}}` (the slides cross-fade, so the static copy must go once the slideshow runs), and the metahotels-core hero preload. Abar: LCP 16.3 s → 5.8 s → 3.2 s with the preload. The URL is hard-coded: tell the owner to update it when slide 1 changes |
| Hero slideshow fix (the Abar row above) needed on several pages or languages | A hard-coded slide URL in custom CSS has to be repeated per page and goes stale | Site plugin reads the first top-level element of the queried page from Elementor (`get_elements_data()`), and when its background is a slideshow prints the preload and the static CSS for its first gallery image (`khalidia-performance.php`, `kph_perf_hero_slide()`). With slide lazy-load on, wait for `.swiper-slide-active .swiper-lazy-loaded` before removing the static copy. Skip Ken Burns "out" (it starts enlarged). Belongs in metahotels-core next to the hero preload |
| Elementor background slideshow "Lazyload" switched on and the hero shows no slides | A theme that ships its own Swiper (Bookora) replaces the build Elementor's slide lazy-loading relies on: 0 of 7 slides ever get their image | Don't enable it; test on the HTML first with a rule that adds `"background_slideshow_lazyload":"yes"` to the container's `data-settings` |
| On a throttled phone the logo, menu and hero heading are missing for seconds after first paint; the LCP element is the hero `H1` and arrives about 2 s after DOMContentLoaded (Shams: first paint 3 s, heading 6.5–8 s) | The header row and the hero text have an Elementor entrance animation. Elementor keeps such elements `visibility:hidden` (`.elementor-invisible`) until its own JavaScript has loaded and started. `scripts/wp/entrance.py` counts them per header template and first section | Start the same animation from CSS at first paint, for the header and the first section only: `S.elementor-invisible[data-settings*='animation":"fadeInUp"']{visibility:visible;animation-name:fadeInUp;animation-duration:1.25s}`. Elementor later swaps the classes; the animation name is unchanged, so it does not replay (`scripts/checks/entrance-check.js` samples opacity every 50 ms: "fell back 0x"). Site plugin `shams_perf_entrance_css()`, or the metahotels-core switch "Start Header and Hero Animations at First Paint" (`metahotels_enable_entrance_first_paint`, added locally 2026-10-13, needs a release). Shams: LCP 7.6–8.4 s → 2.7–2.8 s. This also removes the reason JS Defer delays LCP on such a page: re-test defer afterwards |
| The first image below a full-screen hero downloads at high priority ahead of the hero (Khalidia: a 344 KB "welcome" image, 1.5 → 7.0 s on Slow 4G) | Elementor's image-loading module counts the header's logos and treats the first three images of the page as on screen; the first large one gets `fetchpriority="high"`. Its threshold is hard-coded: the `wp_omit_loading_attr_threshold` filter does nothing while "Optimized Image Loading" is on | Site plugin, on pages whose first element is a full-height background: filter `wp_content_img_tag` at priority 20 (after Elementor's 10), remove `fetchpriority="high"` and add `loading="lazy"` |
| Hero background video is most of the page weight (Nassima: 3.4 MB of 5.1 MB) | A Custom Code snippet builds a `<video>` with a poster and starts the MP4 on a timer | Start it on first interaction instead (same events); the poster shows until then, as it already did before the timer fired. **Ask first**: mobile visitors see the poster until they touch the page. Re-encoding a 540p, 850 kbps file saves little |
| The hero has no image for seconds after first paint on a throttled phone (Shams: first paint 2.8 s, poster 6.5 s) | The video background builds its poster with JavaScript at DOMContentLoaded | Until the core switch is released: set the video's first frame as the container's own classic background (Shams: 19 KB AVIF, attachment uploaded with `scripts/wp/upload-file.py`). Check the container's leftover `background_image` / `background_image_mobile` first: template demo images become visible when the background type is set |
| Hero with the metahotels-core video background: on a throttled phone the largest paint is the poster at DOMContentLoaded (Gewan: 12.1 / 12.9 / 12.1 s, against 3.6 s with a plain background image the day before), although the poster is preloaded | `vbg.js` builds the poster layer at DOMContentLoaded, and the video file is requested from the start and competes with the page | Per section, Video Background (R2) › "Start After Page Load" (`vbg_after_load`, released in 2.9.8.9): the poster is painted from CSS at first paint and the file is requested after the load event. Use the video's first frame as the poster (`mode=frame` from Media Transformations, re-encoded and uploaded as an attachment), so preload, first paint and video show the same picture. After the save, purge the front page: the MCP save left the QUIC.cloud copy of the homepage stale (check `data-vbg` for `afterLoad`) |
| Owner wants a hero video on R2 in a size per screen (metahotels-core "Video Background (R2)", `vbg_desktop` / `vbg_mobile` / `vbg_poster`, switch at 767 px) | R2 only stores files. Cloudflare Media Transformations resizes them by URL on a zone with Transformations enabled: `https://<zone host>/cdn-cgi/media/mode=video,time=0s,duration=60s,width=1280,fit=scale-down,audio=false/<source url>`; poster with `mode=frame,time=0s,width=1920,format=jpg` | Source must be an MP4 under 100 MB and 10 minutes (a VP9 WebM returned error 9412; a VP9 stream in an MP4 container worked on Gewan and came out as H.264: 1280 px 10.3 MB, 720 px 4.3 MB); output is at most 60 s, always H.264 MP4, and there is no bitrate option, only size (Shams, 60 s: 1920 px 31.7 MB, 1280 px 17.5 MB, 720 px 7.0 MB, 540 px 4.2 MB). One second of output is one billed transformation per distinct URL per month, 5,000 free. It does not react to bandwidth. Test each URL with `curl` and `ffprobe` before saving it, then check playback per viewport with `scripts/checks/probe.js` |
| PageSpeed mobile LCP stuck at 15 s or more although its own trace shows the LCP element at 1–2 s (`metrics` audit: `observedLargestContentfulPaint` against `largestContentfulPaint`), and mobile runs fall into two groups (simulated FCP about 3 s or 7–11 s) | Lighthouse's simulated connection charges everything requested before the observed paint. Shams: a 6.9 MB hero video requested 0.6 s into the load, 1.1 MB of reCAPTCHA, tags. The LCP heading also had a 1.25 s fade-in, and the trace counts it when the fade ends. In the slow group the test machine's first paint (2.3 s) comes after the video request, so even FCP is charged | Order of requests, not LiteSpeed switches: start the hero video after the load event (metahotels-core video background › "Start After Page Load", added locally 2026-10-13, needs a release; it also paints the poster from CSS), reCAPTCHA only when a form is shown, and consider dropping the fade on the LCP heading. `scripts/checks/vbg-afterload.js` shows when the video is requested relative to FCP, LCP and load. Removing the fade alone did not move the score (36 / 54 / 45) |
| Removing a dead background video link makes the section's overlay lighter on desktop | Elementor draws the background overlay on the container and again on the video container; without the video there is one layer | Custom CSS on the container, desktop and tablet only: the same gradient twice with the overlay opacity folded into its colour (`color-mix(in srgb, var(--e-global-color-…) 56%, transparent)`), `opacity:1`. Check which global colour each translated template uses |

## Layout shift

CLS sources from the booking engine, popups, fonts and the logo.

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| Desktop CLS 0.15–0.6 with a `heading`/neighbour widget in the sources moving sideways | A sticky top bar holds a Mirai finder with `width:auto`; it is 0x0 until Mirai renders, then 671x54 | Elementor custom CSS on the wrapper HTML widget: `@media (min-width:768px){ selector{min-width:671px;min-height:54px} }`. **Default fix, no need to ask** (owner, 2026-10-14): it is our wrapper widget, not the booking engine. Measure the finder's settled size per breakpoint and apply it so the finder causes no layout shift |
| Desktop CLS 0.5–0.6 in the first 15 s with the same two elements moving three times (bar 54 → 74 → 54 → 74 px, heading sideways) | Mirai draws the top-bar finder, removes it and draws it again (cookie prompt), and its width grows in steps (475 → 560 → 637 px) | Same wrapper CSS, but reserve with `width` instead of `min-width` so tablets shrink it exactly like the finished finder: `@media (min-width:768px){ selector{width:637px;min-height:54px} }`. Check every breakpoint with `scripts/checks/finder-size.js <url> <rules.json>`: "before" and "after" must be identical. Gevora: 0.53–0.60 → 0.001 |
| Big CLS late in the session (0.25–0.3 desktop, 0.9–1.0 mobile) when a popup opens without a click, **and on a slower connection the page scrolls itself to the footer** (found on Gevora, then confirmed on Abar and Nassima with `scripts/checks/popup-open.js`) | Elementor adds `assets/css/conditionals/dialog.min.css` (1.4 KB) only when the first popup opens and calls `focus()` on the popup's close button 250 ms later. Until that stylesheet arrives the dialog is `position: static` at the end of the page: the layout shifts when it lands, and if it takes longer than the 250 ms the browser scrolls to the focused button and stays there | Print that stylesheet with the page, before `elementor-frontend`: metahotels-core switch "Load Popup Styles With the Page" (`metahotels_enable_popup_dialog_css`, added locally 2026-10-12, needs a release), or the site plugin (`gevora-performance` 1.1.0 `gevora_perf_dialog_css()`). Simulate first with a rule file from `scripts/wp/make-rules.py dialog-css`. A different trigger or a longer delay does not fix it; the booking bar growing is a separate shift (rows below) |
| Desktop CLS ~0.23 about 0.5 s after first paint; sources show the menu `UL` going from two rows to one | The fallback font is wider than the menu's web font, the items wrap and the header is one row taller until the font loads | Custom CSS on the nav-menu widget: `@font-face{font-family:"<x>-fallback";src:local("Arial"),…;size-adjust:<n>%}` and `selector .elementor-nav-menu--main .elementor-item{font-family:"<Web font>","<x>-fallback",sans-serif}`. Find `<n>` by measuring the menu width with web fonts blocked (`scripts/checks/menu-fallback.js`). `flex-wrap:nowrap` alone overlaps the neighbouring column on narrower desktops |
| Small CLS at `load` from the header logo (height 24 → 91 px) | LiteSpeed lazy-loads the above-the-fold logo | LiteSpeed "Lazy Load Image Excludes": the logo's filename |
| Desktop CLS 0.04–0.15 after first paint on pages built on the theme's default template (Gewan: 141 pages), the sources a full-width section | The theme puts the page in a 1200 px container; Elementor widens "stretched" sections to the full screen only when its script runs | Site plugin CSS with the same width from the start: `.<theme container> [data-elementor-type="wp-page"]>.elementor-section-stretched{width:100vw;margin-left:calc(50% - 50vw)}` (`margin-left`, not `left`: Elementor then sets its own left and width, so the final layout is unchanged). `gewan_perf_layout_css()` |
| Mobile CLS from a fixed bottom booking bar growing (Gewan: 57 → 115 px) | The Mirai finder inside the Custom Code bar is empty until the booking engine renders | Reserve its settled height on our own wrapper class (`@media (max-width:766px){.be-mobile [data-mirai-component="finder"]{min-height:58px}}`, same function). Default, no need to ask: our wrapper, not the engine |

## Booking engine, chat, reCAPTCHA and blocking time

Third parties: document the booking engine, never change it.

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| Booking API called many times (`getCurrencyInfo` ×18, `index-price` ×9 on desktop) | Elementor Pro **sticky** clones the sticky container into a hidden `.elementor-sticky__spacer` *before* Mirai loads on `window.load`, so an extra finder mounts in the clone. Hidden-responsive (desktop/mobile) duplicate widgets also initialize | **Document only** (booking engine). A validated fix exists: strip `data-mirai-component` inside `.elementor-sticky__spacer` right before Mirai loads. Mirai cannot re-mount later-added nodes, so don't defer hidden widgets. Also check Custom Code for the same booking-bar block output twice (Nassima: "BE Footer" and "BE - Mobile"). Measured cost on Nassima (`scripts/checks/mirai-dup.js`, duplicates removed only in the test browser): desktop 4 finders instead of 1 = 27 extra requests, 27 KB, about 0.5 s of main-thread blocking after load, ~1,000 DOM nodes; mobile nothing measurable. No effect on FCP/LCP/CLS because Mirai starts after `load` |
| Desktop lab grade stuck around 60–70 with LCP and CLS already good | Total Blocking Time: 30 of 35 lost points on Nassima, and 85–90% of the blocking is the booking engine (blocking `static.mirai.com/core/index.js` in the test browser: 2.2–2.7 s → 0.3 s). Lighthouse gives no TBT points above ~1 s on desktop | Nothing on our side moves it. Show the owner the `psi_breakdown.py` output and the `abhtml.js --block` table; delaying pixels or push SDKs changed nothing measurable on desktop |
| DOMContentLoaded seconds after the HTML arrives (29 s on Slow 4G), Elementor/hero video/booking engine all late | A third-party widget (Nassima: 1.4 MB chatbot) is a synchronous `<script src>` at the end of `<body>` in an Elementor Custom Code snippet | Rewrite the snippet to inject the script on the visitor's first interaction (`scroll`, `mousemove`, `pointerdown`, `touchstart`, `keydown`, each `{once:true, passive:true}`) once the page has loaded, and call its init in `onload`. A timer (e.g. 3 s after `load`) also unblocks the page but test tools still download the script. Check the widget's source for `DOMContentLoaded`/`readyState` handling first. Verify with `scripts/checks/interaction.js` |
| reCAPTCHA (~354 KB JS) on every page | Loaded once by metahotels-core Brevo shortcode on any page with a form, including site-wide popups | metahotels-core toggle "Load reCAPTCHA only when a form is shown" (`metahotels_brevo_recaptcha_lazy`). Needs a released metahotels-core |

## Images and lazy-loading

Weight without scrolling, wrong sizes, lazy-load side effects.

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| A "no scroll, no input" tool reports megabytes of below-the-fold images although `loading="lazy"`, Swiper lazy and Elementor's background lazy-load are all working (Gevora desktop: 8.2 MB) | The popup self-scroll above: any tool that waits past the popup timer sees the page scroll to the bottom and load everything | Fix the popup first. Until it is live, measure weight with the fix simulated: `node $S/weight.js <url> desktop <rules.json> --wait=20000` with a rule file from `scripts/wp/make-rules.py dialog-css`. `scripts/checks/why-eager.js` shows page height, scroll position and image requests over time |
| Megabytes of images load without scrolling although lazy-load is on (`node $S/images.js <url>` shows `bg ... slide` / gallery rows far below the fold) | CSS backgrounds: Media Carousel slides, Jeg portfolio gallery tiles, section backgrounds. LiteSpeed lazy-loads `<img>` only; Elementor's background lazy-load only covers `.e-con` containers, not classic sections | Site plugin: `background-image:none!important` on the 3rd+ top-level element of a page until it is within 800 px of the viewport (see `nassimatower-performance.php`, 1.1.0). Reveal near-viewport elements and ones with a background video/slideshow synchronously, and gate the CSS on a JS-set class |
| Heavy originals (300–450 KB WebP at 1500 px) | Uploaded near-lossless | `scripts/wp/optimize-images.py` → AVIF q50, then `wp_upload.py` (new attachments) and repoint the widgets with `elementor-update-element`. Use WebP, not AVIF, for featured images (social previews) |
| 200 px thumbnails or 400 px cards download 0.4–1.5 MB originals (`images.js` shows `img 200x200` rows with full-size files) | Loop item / Theme Builder templates with `image_size: full` on the Image or Featured Image widget | `elementor-update-element` on the template: `image_size` `medium`, `medium_large` or `large` to fit the slot. `srcset` still serves high-density screens |
| Re-encoded AVIF uploads have no intermediate sizes (`media_details.sizes` empty) although older AVIFs in the library have them | The host's image library cannot write AVIF (any more); WordPress stores the upload and skips the sub-sizes | Fine for backgrounds and slides (they use the full URL). Image widgets then serve the one file to every screen: check it is lighter than the sizes it replaces and compare full-page screenshots for layout. Otherwise upload WebP for image widgets |
| Setting a header logo to a smaller image size and a below-the-fold image suddenly loads at high priority | WordPress gives `fetchpriority="high"` to the first image of at least 50,000 px²; a 300x155 logo no longer qualifies, so the attribute moves to the next eager image | Leave the logo's size alone (Gevora: tried, reverted; the saving was 30 KB) |
| After LiteSpeed "Lazy Load Images" some carousel slides stay blank when the carousel loops (`scripts/checks/late-images.js` reports "never arrived … slide DUPLICATE") | Image Carousel slides with a plain `<img>` (no Swiper lazy): Swiper clones the slides for the loop before LiteSpeed's script has swapped the placeholder, and the clones are never observed | LiteSpeed "Lazy Load Image Parent Class Name Excludes" (`media-lazy_parent_cls_exc`): `swiper-slide`. Check every page type that has a carousel, not only the homepage (Gevora's homepage carousels use Swiper lazy and were fine; `/dining/` and `/amenities-facilities/` broke) |
| After "Lazy Load Iframes" an embedded Google Map stays blank | LiteSpeed 7.9.1 prefixes `data-lazyloaded="1" src="about:blank"` but only renames the original `src` to `data-src` when it is the iframe's first attribute; Elementor's map prints `loading="lazy"` first, so the page gets two `src` attributes and the browser keeps `about:blank` | Leave **Lazy Load Iframes off** (Elementor's embeds already carry native `loading="lazy"`). Check any page with an iframe using `scripts/checks/iframe-check.js` before keeping it |

## Fonts and icon fonts

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| Two Google Fonts origins | Elementor "Load Google Fonts Locally" off | Turn on (identical files, same-origin) |
| After CSS Minify a theme's `fonts.googleapis.com` stylesheet becomes `/wp-content/litespeed/css/…` and lists `.ttf` files | LiteSpeed fetches the external stylesheet without a browser user agent, so Google answers with uncompressed TrueType, no `unicode-range`, no `font-display` | LiteSpeed **CSS Excludes**: `fonts.googleapis.com` (Elementor's own Google Fonts are handled by "Load Google Fonts Locally") |
| 392 KB `jkiticon.woff2` at highest priority on every page | Jeg Elementor Kit ships one icon font with 2,834 glyphs | Site plugin adds a second `@font-face` (same family, printed after Jeg's CSS) with a subset file and a `unicode-range`; the full font stays as the automatic fallback. Guard on the source font's file size. `scripts/wp/build-icon-subset.py` |
| 464 KB `elementskit.woff` (uncompressed, no cache header) on every page | ElementsKit Lite ships one icon font with 915 glyphs; the nav menu's arrows and hamburger use it | Same subset technique as the Jeg font: `scripts/wp/build-icon-subset.py` (14 icons, 2.4 KB woff2). The glyphs can differ by sub-pixel anti-aliasing in a pixel diff; check the crop with `scripts/checks/diffbox.js` |
| After Elementor › Settings › Advanced › "Load Font Awesome 4 Support" is set to No, icons printed as `<i class="fas …">` disappear (Khalidia: the caret of the Connect Polylang language switcher, on every page, for half an hour) | The setting removes Font Awesome's main stylesheet (`font-awesome-5-all`) together with the two `v4-shims` files | Leave the setting on. To drop the compatibility files, dequeue the `font-awesome-4-shim` style and script in the site plugin. General rule: a block test must block every file the switch removes, so read the HTML with the switch on a staging copy or compare handles first |

## Addon and theme assets (site plugin)

Files every page loads for widgets no page uses, and 404s they cause.

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| 404s for `/plugins/elementor-pro/assets/css/widget-{blockquote,mega-menu,nav-menu}.min.css` | Header Footer Elementor 2.9.x hardcodes `plugins_url('/elementor-pro/...')` when any Elementor Pro class exists; Pro Elements lives in `/pro-elements/`. Each 404 = ~22 KB WP 404 page, render-blocking | Site plugin dequeues the HFE handles (if no HFE templates/widgets). LiteSpeed minify also hides them, but that isn't the fix |
| ~11 HFE stylesheets on every page | HFE enqueues eicons, Font Awesome, duplicate icon-list/social-icons CSS globally | Same site plugin, if `elementor-hf` posts = 0 and no HFE widgets in the sweep |
| owl.carousel / superslides / easing / price-table / allscripts JS in `<head>` | Gum Elementor Addon enqueues them during control registration on every page | Dequeue if no `gum_*` widgets. **Keep** Gum `style.css` (Gum adds controls to core widgets) |
| ekit header-search/offcanvas/info CSS+JS + magnific-popup everywhere | ElementsKit Lite force-loads header widget assets "in case" | Dequeue if those widgets aren't used. Widgets re-add their deps when they render |
| 404s for logo files on every page, each answered by the full WordPress 404 page (Khalidia: 245 KB of HTML built in PHP, 2–3 per page view on 102 pages), and a broken image in the footer on phones | The theme's logo widget (`ova_logo`) prints three `<img>` tags (desktop, mobile, sticky) whether or not they are shown; mobile and sticky pointed at deleted files | Point both at the widget's own desktop logo (`scripts/wp/fix-footer-logos.py`), and set the mobile height to the logo's proportions where the widget is visible on phones |
| A site plugin's `wp_dequeue_style()` at `wp_enqueue_scripts` priority 100 has no effect; the files are still printed on every page (Gewan: WP Job Openings + Pro Pack) | Another plugin enqueues them again later in the request (Pro Pack, whose source is not public, with its own dependencies) | Dequeue at `wp_enqueue_scripts` `PHP_INT_MAX`, again at `wp_print_styles` `PHP_INT_MAX` and at `wp_print_footer_scripts` priority 1 (`gewan-performance.php` 1.0.1). A block test in the browser does not prove the PHP side: check the marker on every page after the upload |

## LiteSpeed, cache, CDN and host

| Symptom | Root cause (where found) | Fix |
|---|---|---|
| After JS Minify, third-party `<script src>` tags point to `/wp-content/litespeed/js/` | "Combine External and Inline" also applies to minify: LiteSpeed copies external JS locally and freezes it | LiteSpeed **JS Excludes**: every third-party script host in the HTML (chat, Brevo, booking engine) |
| Some post types still show the old HTML after a snippet or template save although pages are fresh | Behind QUIC.cloud the automatic purge covered pages but left posts and custom post types on the edge (`x-qc-cache: hit`, old "Page cached by LiteSpeed" date) | One "Purge All – LSCache" (`purge_all_lscache`) at the end of the batch, then re-warm |
| JS without Cache-Control, CSS/img 12h | Host-level config. LiteSpeed Browser Cache writes `mod_expires` to `.htaccess` but the server ignores it | Hosting panel / host support. Don't hand-edit `.htaccess` without file access to roll back |
